## Различия старого PR и текущего кода

- Класс .form_error из старого замечания НЕАКТУАЛЕН. Текущий шаблон rfr-auth/src/main/resources/templates/login.html содержит .form__error.form__alert, с двумя подчёркиваниями. LoginPage проверяет фактический элемент. Auth-шаблон и бизнес-логика не менялись ради старого селектора.
- Сервер локализует ошибку. Первый запуск с точным Bad credentials получил русский текст и упал. Ожидание не ослаблено: штатный @UsePlaywright(EnglishContext.class) теперь задаёт en-US, и оба негативных сценария требуют точный Bad credentials. Page/BrowserContext по-прежнему создаёт framework.
- Новое уточнение пользователя о rfr_ имеет приоритет над прежней документацией ui_. Исторические отчёты о старых ui_-данных сохранены как история, а действующий skill исправлен.

## Изменённые файлы и причины

Пути Java относительны rfr-e2e/src/test/java/io/student/rangiffler.

- page/LoginPage.java: действие отправки неверных данных и проверка видимой ошибки .form__error с точным текстом.
- test/auth/LoginTest.java: два отсутствовавших негативных сценария; положительный сохранён.
- config/EnglishContext.java: штатная фабрика параметров контекста для английского сообщения, без самостоятельного создания браузера.
- page/ProfilePage.java: поля, выбор страны, загрузка, Save с waitForResponse(UpdateUser), Reset, reload и проверки сохранённого профиля/аватара.
- test/profile/ProfileTest.java: пять независимых сценариев на собственном @User. PNG генерируется в памяти, временные файлы не нужны. Превью проверяется до Save, чтобы исключить гонку с FileReader.
- utils/RandomDataUtils.java: rfr_ + 32 hex UUID вместо ui_.
- test/utils/RandomDataUtilsTest.java: 127 имён должны быть уникальны и соответствовать rfr_[0-9a-f]{32}.
- test/data/db/{AuthAccountTest,FriendshipTest,FriendshipsTest,ProfileTest}.java и test/fixture/RegistrationFixtureTest.java: прямые тестовые имена приведены к rfr_.
- test/fixture/RegistrationFixtureTest.java: проверены обе схемы после успеха и намеренного падения после Profile; прежние падения до профиля/аккаунта сохранены.
- test/fixture/SingleUserFixtureTest.java: повторное закрытие не оставляет auth/API-пользователя.
- test/fixture/TearDownTest.java: ошибка API-cleanup не пропускает auth-cleanup и не теряется.
- .agents/skills/rfr-test-data/SKILL.md: действующий rfr_, сохранён поиск старых ui_; 24 строки, корректный frontmatter.

SingleUserFixture, RegistrationFixture, TearDown и SQL-механизмы очистки не переписывались. Удаление адресное по username. Ошибки шагов Teardown независимы. SQL по-прежнему находится в data/db и resources/sql. Префикс не участвует в адресном удалении, поэтому смена имени не меняет семантику cleanup. Широкие DELETE/TRUNCATE не добавлялись.

## Независимое ревью

Запущен test-reviewer, задача /root/luroy_review, затем выполнено дополнительное чтение финального .form__error и EnglishContext. Субагент не менял код и не запускал тесты, чтобы не конкурировать со стендом.

Вывод финального дополнения: **«Новых подтверждённых дефектов в финальных изменениях не обнаружено».**

Ревьюер подтвердил: .form__error — актуальная разметка; EnglishContext задаёт язык через поддерживаемый OptionsFactory и не ослабляет assertion; Save проверяется reload, preview аватара устраняет гонку FileReader, Reset сравнивается с сохранённым baseline; очистка регистрации и обеих БД сохраняет правильное владение ресурсами.

Ограничения: старый PR не был доступен, оценивались требования из сообщения; невозможность любых flaky-сбоев не доказывается одним полным прогоном; старые остатки ui_ не устранены. Новые исходники пока untracked — их нужно включить в будущий коммит, когда будет отдельный запрос. Коммиты и PR автоматически не создавались.
