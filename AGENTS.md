# Repository Guidelines

## Структура проекта

- `rfr-api/` — сервер GraphQL на Spring Boot. Исходники расположены в `src/main/java/io/student/rangiffler`, схемы GraphQL, миграции Flyway и JSON-заглушки — в `src/main/resources`.
- `rfr-auth/` — сервер авторизации OAuth; ресурсы содержат настройки и шаблоны страниц.
- `rfr-e2e/` — модуль автоматизированных тестов; тестовые классы находятся в `src/test/java/io/student/rangiffler`.
- `rfr-gql-client/` — клиент React и TypeScript: компоненты, страницы, хуки и обращения к API находятся в `src/`, статические ресурсы — в `public/`.

Корневая сборка Gradle объединяет три Java-модуля. Клиент собирается отдельно через npm.

## Сборка, тестирование и локальный запуск

Используйте JDK 25 и Gradle Wrapper из репозитория. Команды ниже предназначены для PowerShell; в Bash заменяйте `./gradlew.bat` на `./gradlew`.

- `./gradlew.bat build` — собрать Java-модули и выполнить тесты.
- `./gradlew.bat runAll` — параллельно запустить авторизацию на порту 9001 и API на порту 8081. Перед запуском должна работать MySQL.
- `./gradlew.bat :rfr-auth:bootRun` — запустить авторизацию на порту 9001.
- `./gradlew.bat :rfr-api:bootRun` — запустить API на порту 8081.
- `./gradlew.bat :rfr-e2e:test` — выполнить тесты JUnit.
- `./gradlew.bat e2e` — выполнить все тесты модуля `rfr-e2e`. Перед запуском должны работать MySQL, авторизация, API и фронтенд.
- В каталоге `rfr-gql-client`: `npm ci` устанавливает зависимости, `npm run dev` запускает клиент на порту 3001.
- Там же `npm run build` проверяет TypeScript и собирает приложение; `npm run lint` запускает ESLint без допустимых предупреждений.

## Стиль кода и именование

Сохраняйте стиль соседних файлов: Java обычно использует отступы в два пробела, TypeScript и Gradle — в четыре. Классы Java и компоненты React называйте в PascalCase, методы и переменные — в camelCase, хуки — с префиксом `use`. Используйте пакет `io.student.rangiffler` и существующую конфигурацию ESLint. Миграции называйте `V<number>__description.sql`. Сгенерированные модели GraphQL в `build/generated/` вручную не редактируйте.

## Требования к тестам

Настроены JUnit Jupiter 6, Playwright Java и Allure. Называйте классы `*Test.java`, методы — по проверяемому поведению. Сейчас набор тестов представляет собой заготовку; числовой порог покрытия не задан. Добавляйте позитивные и негативные сценарии, особенно проверки прав доступа и ошибок GraphQL. Перед браузерными тестами запускайте необходимые сервисы. Отдельная команда тестирования клиента пока отсутствует.

## Коммиты и запросы на слияние

История содержит короткие повелительные заголовки, например `Resize map component`. Сохраняйте краткость и посвящайте коммит одной задаче. В запросе на слияние опишите изменение поведения, укажите связанные задачи и результаты проверок. Для изменений интерфейса приложите снимки экрана; изменения конфигурации и схем документируйте.

## Настройки и безопасность

Для локального запуска требуется MySQL; порядок настройки описан в `README.md`. `localenv.sh` запускает MySQL через Docker Compose с ожиданием готовности. Не добавляйте в коммиты секреты и токены.

## Permissions

В `.codex/hooks.json` настроен синхронный `PostToolUse` для Windows/PowerShell: после изменения Java запускается `compileTestJava` затронутого модуля (без выполнения тестов), после изменения исходников или конфигурации фронтенда — `npm run build`. Вывод и код завершения возвращаются в контекст агента; ошибки необходимо исправить. `SessionStart` сохраняет исходный снимок файлов, повторные вызовы без изменений не запускают сборку. Полные логи и снимки находятся в системном временном каталоге. После добавления или изменения хуков перезапустите Codex и подтвердите доверие конфигурации хуков в интерфейсе; автоматическое срабатывание требует доверенного слоя `.codex` проекта.

- Разрешено без дополнительного согласования запускать, останавливать и перезапускать локальные auth, API, фронтенд, MySQL и тесты этого проекта, когда это нужно для текущей задачи.
- Для бекендов используйте `runAll` или соответствующий `bootRun`, для фронтенда — `npm run dev`, для тестов — `e2e` или `:rfr-e2e:test`, для MySQL — Compose либо `docker start/stop rfr-mysql`. Разрешены сборка, компиляция, lint и установка зависимостей проекта.
- Перед остановкой процесса проверьте PID, командную строку и принадлежность Rangiffler. Не останавливайте все процессы Java, Node.js или все Docker-контейнеры. При остановке тестов завершайте только соответствующий запуск, а не все демоны Gradle.
- Удаление файлов и каталогов через `rm`, `Remove-Item`, `del`, `rmdir` и аналоги запрещено. Вместо удаления переименовывайте объект в `<имя>.bak` внутри рабочей директории проекта. Проверяйте абсолютный путь; если `.bak` уже существует, используйте уникальный суффикс, не перезаписывая резервную копию. Резервные копии не добавляйте в коммиты.
- Не удаляйте Docker volumes и данные MySQL; `docker compose down -v`, `docker volume rm` и очистка Docker не входят в эти разрешения.
- Эти разрешения выражают согласие пользователя на операции проекта и не отменяют ограничения sandbox и управляемой политики среды.
